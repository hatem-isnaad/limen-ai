Build production-ready AI agents in Laravel

Limen AI is a reusable Laravel package for config-driven agents, tools, skills, workflows, memory, knowledge retrieval (RAG), approvals, and an embeddable chat UI — with authorization, SSRF protection, and audit logging built in from day one.

Quick start (5 min) GitHub repository

Core principle

Every design decision follows one rule:

The LLM proposes actions. Laravel decides whether they are allowed and executes them safely.

User identity, permissions, data scoping, and side effects never come from model output — they come from your authenticated Laravel context, Gates, and host application services.

Config-first

Define agents, tools, and workflows in PHP config — no redeploy to switch models or providers.

Host-owned logic

Business rules live in App\LimenAi\Tools\ and your services — the package stays domain-agnostic.

Test without LLM bills

FakeLlmProvider queues deterministic responses for fast CI and local development.

Installation

Install into an existing Laravel 11 or 12 app. Packagist is optional — see installation.md for VCS, path repo, private registry, and monorepo methods.

1. Require the package

Shell
# Packagist
composer require limen-ai/limen-ai

# Or VCS (add repository to composer.json first)
composer update limen-ai/limen-ai

# Or local path repo for development
# See installation.md

2. Publish assets

Shell
php artisan limen-ai:install
# Or publish individually:
# php artisan vendor:publish --tag=limen-ai-config
# php artisan vendor:publish --tag=limen-ai-env

3. Run migrations & validate

php artisan limen-ai:validate

Quick start

Ship a working chat agent in four steps.

Step 1 — Register a tool class

PHP
// app/LimenAi/Tools/ExampleEchoTool.php
namespace App\LimenAi\Tools;

use LimenAi\Contracts\Tools\Tool;
use LimenAi\Contracts\Tools\ToolDefinition;
use LimenAi\Contracts\Runtime\ToolExecutionContext;
use LimenAi\Tools\ConfigToolDefinition;

class ExampleEchoTool implements Tool
{
    public function key(): string { return 'example_echo'; }

    public function definition(): ToolDefinition
    {
        return ConfigToolDefinition::fromConfig('example_echo', [
            'name' => 'Example Echo',
            'description' => 'Echoes input back for testing.',
            'class' => self::class,
            'input_schema' => ['message' => ['type' => 'string', 'required' => true]],
        ]);
    }

    public function handle(array $input, ToolExecutionContext $context): array
    {
        return ['message' => $input['message'], 'user_id' => $context->userId()];
    }
}

Step 2 — Point config at your tool

PHP
// config/limen-ai.php
'tools' => [
    'example_echo' => [
        'class' => App\LimenAi\Tools\ExampleEchoTool::class,
        // ... other fields from published config
    ],
],

Step 3 — Embed the chat UI

Blade
<x-limen-ai::chatbot agent="example" />

<!-- Floating widget -->
<x-limen-ai::widget agent="example" />

Step 4 — Test with the fake provider

Shell
php artisan limen-ai:agent:test example
composer test

Architecture

Modular layers keep AI orchestration separate from your business logic.

User Message ↓ ConversationService ↓ AgentRuntime::run() ↓ ContextBuilder (auth, memory, knowledge, history) ↓ LlmProvider::chat() ↓ Tool call requested? ──No──→ Final response │ Yes ↓ ToolPipeline ├─ Authorization (Gates) ├─ Input validation ├─ Approval gate (if required) ├─ Idempotency check ├─ Execute host tool / HTTP integration └─ Audit + events ↓ LlmProvider (with tool result) → persist + broadcast
Package

Runtime & orchestration

Agents, tools pipeline, workflows, memory, knowledge, UI components, observability.

Host app

Business & data

Eloquent models, policies, domain services, tool implementations under App\LimenAi\.

Agents

An agent binds instructions, provider, tools, skills, memory policy, and authorization into one deployable unit.

PHP
'agents' => [
    'customer_support' => [
        'name' => 'Customer Support',
        'provider' => 'openai',
        'model' => env('SUPPORT_MODEL', 'gpt-4.1-mini'),
        'instructions' => 'You are a helpful support agent. Use tools for lookups.',
        'persona' => [
            'display_name' => 'Support Assistant',
            'tone' => 'professional',
            'language' => 'auto',
        ],
        'tools' => ['get_shipment_status'],
        'authorization' => ['required' => true, 'abilities' => ['support.use']],
        'limits' => ['max_tool_calls' => 10, 'temperature' => 0.2],
    ],
],

Tools

Tools are Laravel classes or declarative HTTP integrations the LLM can invoke — always through authorization and validation.

Class-based tool

PHP
'get_shipment_status' => [
    'name' => 'Get Shipment Status',
    'class' => App\LimenAi\Tools\GetShipmentStatusTool::class,
    'input_schema' => [
        'shipment_id' => ['type' => 'string', 'required' => true],
    ],
    'authorization' => ['abilities' => ['shipments.read']],
    'confirmation' => false,
],

Tool pipeline guarantees

  • Authorization via Laravel Gates before execution
  • Schema validation on all LLM-provided arguments
  • Human approval pause for sensitive tools (confirmation: true)
  • Idempotency guards and SSRF validation on outbound HTTP
  • Audit logging with sensitive field redaction

Workflows

Multi-step automations with agent steps, tool steps, branches, and approval gates.

PHP
'workflows' => [
    'shipment_notify' => [
        'start' => 'draft',
        'steps' => [
            'draft' => ['type' => 'agent', 'agent' => 'limen_3pl', 'next' => 'approve_send'],
            'approve_send' => ['type' => 'approval', 'next' => 'send'],
            'send' => ['type' => 'tool', 'tool' => 'send_customer_message'],
        ],
    ],
],

Memory & knowledge (RAG)

Inject scoped memory and retrieved documents into every agent turn.

  • Conversation memory — recent context within a thread
  • User memory — persisted preferences scoped to authenticated users
  • Strict policy — key allowlists, regex validation, value truncation
PHP
'knowledge' => [
    'driver' => env('LIMEN_AI_KNOWLEDGE_DRIVER', 'config'),
    'collections' => [
        'getting_started' => [
            'documents' => [
                ['content' => 'Limen AI tools require Laravel authorization.'],
            ],
        ],
    ],
],

Programmatic API

Run agents from controllers, jobs, or listeners — without the HTTP layer or Blade UI.

PHP
use LimenAi\Contracts\Runtime\AgentRuntime;
use LimenAi\Runtime\RunContextData;

$runId = app(AgentRuntime::class)->run(
    agent: 'example',
    conversationId: 'conv-' . $user->id,
    message: 'Summarize open tickets for today.',
    context: RunContextData::make(['user_id' => $user->id]),
);
RunContextData is server-derived

Always pass the authenticated user ID from Laravel — never from LLM output or client-supplied JSON.

Security

Defense in depth — the LLM never becomes your authorization layer.

Authentication (Laravel Guards) ↓ Agent authorization (abilities) ↓ Server-derived RunContext (user ID) ↓ Prompt injection sanitization ↓ Tool authorization + validation ↓ Approval gate for sensitive tools ↓ SSRF-safe HTTP + audit log

See SECURITY.md for the full threat model. Install guide: installation.md.

Observability

  • trace_id — correlates run, LLM calls, and tool spans
  • Audit actions: agent.started, tool.completed, agent.failed
  • Usage metrics: prompt/completion tokens per provider/model
  • Export via GET /limen-ai/runs/{id}/observability
