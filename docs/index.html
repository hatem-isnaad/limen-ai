Build production-ready AI agents in Laravel

Limen AI is a reusable Laravel package for config-driven agents, tools, skills, workflows, memory, knowledge retrieval (RAG), approvals, and a embeddable chat UI — with authorization, SSRF protection, and audit logging built in from day one.

Quick start (5 min) GitHub repository

Core principle

Every design decision follows one rule:

The LLM proposes actions. Laravel decides whether they are allowed and executes them safely.

User identity, permissions, data scoping, and side effects never come from model output — they come from your authenticated Laravel context, Gates, and host application services.

Config-first

Define agents, tools, and workflows in PHP config — no redeploy to switch models or providers.

Host-owned logic

Business rules live in App\LimenAi\Tools\ and your services — the package stays domain-agnostic.

Test without LLM bills

FakeLlmProvider queues deterministic responses for fast CI and local development.

Installation

Complete setup from zero to a working agent in your Laravel application.

1. Require the package

composer require limen-ai/limen-ai

2. Publish assets

php artisan vendor:publish --tag=limen-ai-config
php artisan vendor:publish --tag=limen-ai-views
php artisan vendor:publish --tag=limen-ai-assets
php artisan vendor:publish --tag=limen-ai-migrations

3. Run migrations & validate

php artisan migrate
php artisan limen-ai:doctor
php artisan limen-ai:validate

4. Configure environment

Quick start

Ship a working chat agent in four steps.

Step 1 — Register a tool class

// app/LimenAi/Tools/ExampleEchoTool.php
namespace App\LimenAi\Tools;

use LimenAi\Contracts\Tools\Tool;
use LimenAi\Contracts\Tools\ToolDefinition;
use LimenAi\Contracts\Runtime\ToolExecutionContext;
use LimenAi\Tools\ConfigToolDefinition;

class ExampleEchoTool implements Tool
{
    public function key(): string { return 'example_echo'; }

    public function definition(): ToolDefinition
    {
        return ConfigToolDefinition::fromConfig('example_echo', [
            'name' => 'Example Echo',
            'description' => 'Echoes input back for testing.',
            'class' => self::class,
            'input_schema' => ['message' => ['type' => 'string', 'required' => true]],
        ]);
    }

    public function handle(array $input, ToolExecutionContext $context): array
    {
        return ['message' => $input['message'], 'user_id' => $context->userId()];
    }
}

Step 2 — Point config at your tool

// config/limen-ai.php
'tools' => [
    'example_echo' => [
        'class' => App\LimenAi\Tools\ExampleEchoTool::class,
        // ... other fields from published config
    ],
],

Step 3 — Embed the chat UI

<x-limen-ai::chatbot agent="example" />

<!-- Floating widget -->
<x-limen-ai::widget agent="example" />

Step 4 — Test with the fake provider

php artisan limen-ai:agent:test example
composer test

Architecture

Modular layers keep AI orchestration separate from your business logic.

User Message ↓ ConversationService ↓ AgentRuntime::run() ↓ ContextBuilder (auth, memory, knowledge, history) ↓ LlmProvider::chat() ↓ Tool call requested? ──No──→ Final response │ Yes ↓ ToolPipeline ├─ Authorization (Gates) ├─ Input validation ├─ Approval gate (if required) ├─ Idempotency check ├─ Execute host tool / HTTP integration └─ Audit + events ↓ LlmProvider (with tool result) → persist + broadcast

Agents

An agent binds instructions, provider, tools, skills, memory policy, and authorization into one deployable unit.

'agents' => [
    'customer_support' => [
        'name' => 'Customer Support',
        'description' => 'Helps authenticated users with orders and shipments.',
        'model' => env('SUPPORT_MODEL', 'gpt-4.1-mini'),
        'provider' => 'openai',
        'instructions' => 'You are a helpful support agent. Use tools for lookups.',
        'persona' => [
            'display_name' => 'Support Assistant',
            'tone' => 'professional',
            'language' => 'auto',
            'response_style' => 'concise',
            'rules' => ['Never invent order or shipment data.'],
        ],
        'skills' => ['general_assistance'],
        'tools' => ['get_shipment_status'],
        'knowledge' => ['shipping_policy'],
        'memory' => [
            'conversation' => true,
            'user' => true,
            'allowed_keys' => ['preferred_language', 'timezone'],
        ],
        'authorization' => [
            'required' => true,
            'abilities' => ['support.use'],
            'guest_allowed' => false,
        ],
        'limits' => [
            'max_tool_calls' => 10,
            'max_steps' => 20,
            'temperature' => 0.2,
            'max_tokens' => 1200,
        ],
        'version' => '1.0.0',
    ],
],

Tools

Tools are Laravel classes or declarative HTTP integrations the LLM can invoke — always through authorization and validation.

Class-based tool

'get_shipment_status' => [
    'name' => 'Get Shipment Status',
    'description' => 'Look up shipment by ID.',
    'class' => App\LimenAi\Tools\GetShipmentStatusTool::class,
    'input_schema' => [
        'shipment_id' => ['type' => 'string', 'required' => true],
    ],
    'authorization' => ['abilities' => ['shipments.read']],
    'confirmation' => false,
    'timeout' => 10,
],

HTTP integration tool

'example_http_status' => [
    'name' => 'Example HTTP Status',
    'integration' => [
        'connector' => 'example_api',
        'method' => 'GET',
        'path' => '/status/{{ input.resource }}',
    ],
    'input_schema' => [
        'resource' => ['type' => 'string', 'required' => true],
    ],
],

Tool pipeline guarantees

  • Authorization via Laravel Gates before execution
  • Schema validation on all LLM-provided arguments
  • Human approval pause for sensitive tools (confirmation: true)
  • Idempotency guards for side-effect operations
  • SSRF validation on outbound HTTP
  • Audit logging with sensitive field redaction

Workflows

Multi-step automations with agent steps, tool steps, branches, and approval gates.

'workflows' => [
    'shipment_notify' => [
        'name' => 'Shipment Delay Notification',
        'start' => 'draft',
        'steps' => [
            'draft' => [
                'type' => 'agent',
                'agent' => 'limen_3pl',
                'message' => 'Draft a professional delay notification.',
                'next' => 'approve_send',
            ],
            'approve_send' => [
                'type' => 'approval',
                'message' => 'Approve sending the customer notification?',
                'next' => 'send',
            ],
            'send' => [
                'type' => 'tool',
                'tool' => 'send_customer_message',
                'input' => [
                    'shipment_id' => '{{ input.shipment_id }}',
                    'message' => '{{ step_outputs.draft.output }}',
                ],
            ],
        ],
    ],
],

Memory & knowledge (RAG)

Inject scoped memory and retrieved documents into every agent turn.

Memory

  • Conversation memory — recent context within a thread
  • User memory — persisted preferences scoped to authenticated users
  • Strict policy — key allowlists, regex validation, value truncation

Knowledge collections

'knowledge' => [
    'driver' => env('LIMEN_AI_KNOWLEDGE_DRIVER', 'config'),
    'collections' => [
        'getting_started' => [
            'documents' => [
                ['content' => 'Limen AI tools require Laravel authorization.', 'metadata' => ['source' => 'docs']],
            ],
        ],
    ],
],

Set knowledge.driver to vector with OpenAI embeddings for production RAG.

Programmatic API

Run agents from controllers, jobs, or listeners — without the HTTP layer or Blade UI.

use LimenAi\Contracts\Runtime\AgentRuntime;
use LimenAi\Runtime\RunContextData;

$runId = app(AgentRuntime::class)->run(
    agent: 'example',
    conversationId: 'conv-' . $user->id,
    message: 'Summarize open tickets for today.',
    context: RunContextData::make(['user_id' => $user->id]),
);

// Poll run status
$run = app(\LimenAi\Contracts\Runtime\RunRepository::class)->find($runId);
// $run['status'], $run['final_message']
RunContextData is server-derived. Always pass the authenticated user ID from Laravel — never from LLM output or client-supplied JSON.

Conversation service

use LimenAi\Conversations\ConversationService;

$service = app(ConversationService::class);
$conversation = $service->start('example', RunContextData::make(['user_id' => 1]));
$messages = $service->storedMessages($conversation['id']);

Queue & realtime

Offload long agent runs to the queue and stream updates to the chat UI.

Background agent runs

# .env
LIMEN_AI_QUEUE_AGENT_RUNS=true
LIMEN_AI_QUEUE_CONNECTION=redis
LIMEN_AI_QUEUE=default

When enabled, message endpoints return immediately with a run_id while the worker processes the agent loop.

Broadcasting (Pusher-compatible)

# .env
LIMEN_AI_BROADCASTING_ENABLED=true
LIMEN_AI_BROADCAST_DRIVER=pusher
LIMEN_AI_BROADCAST_CHANNEL_PREFIX=limen-ai.conversation

The chat widget listens on {prefix}.{conversationId} for message and run status events — no polling required in production.

Security

Defense in depth — the LLM never becomes your authorization layer.

Authentication (Laravel Guards) ↓ Agent authorization (abilities) ↓ Server-derived RunContext (user ID, never from LLM) ↓ Prompt injection sanitization on untrusted content ↓ Tool authorization + validation ↓ Approval gate for sensitive tools ↓ SSRF-safe HTTP integrations ↓ Output redaction + audit log

Never trust from LLM output

  • User IDs, tenant IDs, or permission decisions
  • Record ownership claims
  • Raw URLs for server-side fetch without SSRF checks

See SECURITY.md for the full threat model.

Observability

Trace IDs, audit logs, and token usage tracking for every run.

  • trace_id — correlates run, LLM calls, and tool spans
  • Audit actions: agent.started, tool.completed, agent.failed, etc.
  • Usage metrics: prompt/completion tokens per provider/model
  • Export via GET /limen-ai/runs/{id}/observability

Use cases

Real-world patterns you can implement today with Limen AI.

Support

1. Customer support chatbot

Authenticated users ask about orders. Agent uses get_order_status tool backed by your Eloquent models. Gates enforce orders.read. Memory stores preferred language.

<x-limen-ai::widget agent="customer_support" />
Operations

2. Internal ops assistant (Limen 3PL)

Warehouse operators look up shipments and draft customer notifications. Outbound messages require human approval before send_customer_message executes.

User: "Where is shipment 12345?"
→ get_shipment_status → summarized reply

User: "Notify customer about delay on 67890"
→ drafts message → approval UI → send on approve
Multi-model

3. Route agents to different LLM providers

Run cheap models for triage, premium models for complex reasoning — per agent in config. No code changes when switching vendors.

Compliance

4. Approval-gated sensitive actions

Set confirmation: true on tools that send emails, charge cards, or delete data. Runtime pauses until an authenticated operator approves in the chat UI or via API.

Automation

5. Workflow-driven batch notifications

Use shipment_notify workflow: agent drafts → approval step → tool sends. Ideal for operational playbooks with human oversight.

RAG

6. Policy-aware knowledge assistant

Load handbook documents into a knowledge collection. Agent retrieves relevant chunks each turn. Content is sanitized before injection to mitigate prompt injection.

API

7. Custom React/Vue frontend

Skip Blade components — call the HTTP API directly from your SPA. Poll /runs/{id} or subscribe to Pusher channels for live updates.

Testing

8. CI-safe agent tests

Queue responses on FakeLlmProvider, assert tool calls and authorization — zero API spend in CI.

$fake = app(FakeLlmProvider::class);
$fake->queueResponse(LlmResponseData::fromArray([
    'content' => 'Done.',
    'tool_calls' => [[
        'id' => 'call_1', 'type' => 'function',
        'function' => ['name' => 'example_echo', 'arguments' => '{"message":"hi"}'],
    ]],
]));
